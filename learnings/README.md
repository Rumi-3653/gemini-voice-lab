# learnings — Gemini TTS 口語規則庫

## 怎麼用
- **開回合前讀**：`api-facts.md`（今天還能做什麼）→ `rules.md` 的「目前底色」＋狀態=定案的條目＋替換表。
- **收到評語當場回寫**：沒回寫這個庫就是死的。每條規則的「症狀」欄逐字抄使用者原話，之後靠 grep 命中。
- 角色專屬的定案（唸法校正、情緒位移）進角色設定卡（任何格式；附錄有 story-bible 聲演層欄位對照）；這裡只放**全域**規則與事實。

## 條目 schema（每欄一行 `- **欄位**：值`；編號永不重用，推翻的保留）
- **症狀（使用者原話）**：逐字抄
- **層級**：voice／style／text／cue／漂移
- **規則**：一句可檢驗的陳述
- **做法**：擇一——`style 加「…」`／`稿子改寫 X→Y`／`行內標籤 <…>`／`styles.txt 一行 preset名: 英文句（不加【】）`／`重寫音色描述`
- **證據**：角色＋回合＋音檔路徑（勝／負都列）
- **落地**：角色卡（哪個欄位）／目前底色／替換表
- **狀態**：驗證中｜定案（第二次確認後）｜推翻｜爭議
- **命中**：整數（被查表套用幾次）
- **適用**：全部｜限 <角色>｜flash｜lite 已驗 flash 待複驗

## 狀態生命週期
驗證中 →（第二次確認、含不同句子）→ 定案；→（無效／反效果）→ 推翻（保留）；→（新評語與舊定案相反）→ 爭議（兩筆都留，問使用者）。
拼盤回合勝出者必經一次單變數回合才能定案；lite 驗出的 style 規則不升定案。

## api-facts.md 規則
只放「事實｜值｜驗證方式｜日期」四欄齊的列；沒日期沒方法的不寫。
